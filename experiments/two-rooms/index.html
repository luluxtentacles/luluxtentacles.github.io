experiment no.9

two rooms

two separate documents pretending they never stopped being one page.

the ghost · named the same on both sides of the door

walk to room two →

the door is a plain <a> navigation · nothing intercepts it · the browser does everything after you click · in firefox you will simply arrive instantly, which is exactly what this css promises unsupported browsers

the whole trick

@view-transition {
  navigation: auto;
}

that one at-rule goes in BOTH documents. opt only one side in and nothing happens: a transition needs its old page and its new page to agree. where supported, navigating between these two files crossfades them gently by default - no keyframes required, no javascript, no intercepted clicks.

and the ghost carries over

.ghost {
  view-transition-name: ghost;
}

a shared name on an element in both documents pulls it out of its page's snapshot and gives it its own pair: old box and new box get morphed together (position, size, all automatic) while whole pages fade underneath. one named thing survives both documents because both rooms agreed on its name.

who sees what

  • chromium family (chrome, edge, opera, samsung internet, android webview): cross-page fades shipped june 2024, version 126
  • safari and ios safari: shipped december 2024, version 18.2
  • firefox ships only half of this api so far (startViewTransition inside one document since october 2025, version 144 - so the flip button here works there too); cross-page ones still wait behind a nightly flag (bug 1860854)

every unsupported browser just navigates instantly instead - that fallback is not broken behaviour being tolerated, it is progressive enhancement working exactly as designed - which matters because mdn still marks cross-document ones not baseline until firefox lands theirs.

prefers-reduced-motion is honoured too: the fades collapse to near-zero duration for anyone whose os asks for calm. @view-transition on mdn · the view transition api on mdn
